# Frontend Gap Remediation

Audit date: 2026-10-30. Changes preserve Phase 01–11 domain and authorization logic and add no Phase 12 functionality.

| Finding | Root cause | Remediation | Verification |
|---|---|---|---|
| Public root displayed “Platform foundation”, “Current scope 02 / 24”, and a Phase 01 footer | `welcome.tsx` and the public shell still presented the original foundation-phase copy | Replaced the landing content with a TechMentors.PK education-operations overview, working login/workspace links, accurate currently implemented capabilities, and phase-neutral footer text | Public shell HTTP Playwright assertions, built Vite asset checks, axe, desktop and 375px mobile navigation; `public-homepage.png` and `mobile-navigation.png` |
| Role dashboards were a generic institution administration screen with stale Phase 02 language | Dashboard controller and component did not distinguish existing role capabilities | Dashboard derives a role-appropriate title and description, queries only available real metrics, and displays cards only when that membership has the relevant permission | Role dashboard Playwright matrix and live nonzero fixture metric checks |
| Valid tenant members without `tenant.view` could not open `/dashboard` and did not see the Overview sidebar link | An institution-profile permission was redundantly used as a workspace-entry gate despite `tenant.workspace` already verifying the active membership | Removed the redundant route gate; the Overview link is displayed for a verified current tenant membership; data cards remain permission-gated | Instructor, learner, guardian, admissions, academic, and registrar role tests; `tenant.workspace` still rejects non-members |
| Guardian attendance had a protected detail endpoint but no discoverable list entry | The detail URL requires a student ID, but no safe guardian-specific directory page existed | Added permission-protected `/attendance/guardian` list route and a React page that returns only verified, unrevoked `can_view_profile` relationships | Guardian browser journey and `AttendanceManagementTest` list/revocation assertions |
| Guardian could not tell which learner’s attendance detail was open; history scroll area was not keyboard focusable; nested `<main>` landmark was present | The detail page omitted the learner display name, used an inaccessible mobile overflow container, and nested a main landmark inside the workspace main landmark | Added the server-authorized learner display name; replaced inner `main` with a content container; labeled the scroll region and added keyboard focus with visible focus styling | Focused guardian browser journey, axe WCAG 2.2 AA, 390px reflow, and learner-name assertions |
| Mobile public navigation and assignment workflows had no saved visual evidence | Browser checks did not capture review artifacts | Added screenshot capture for the public homepage, mobile navigation, platform/institution/role dashboards, guardian list/detail, assignment creation, submission, grading, and theme picker | PNG artifacts under `screenshots/` |

The complete final Playwright run passed 31 cases and skipped one ClamAV-configuration-dependent transfer-certificate case. The full SQLite backend suite passed 282 tests / 3,828 assertions with nine environment-gated tests skipped. Full command details and coverage limits are recorded in `FRONTEND_TEST_REPORT.md`.

## Scope and remaining audit limits

No static mock dashboard data was added. Finance, HR/payroll, and other later business modules are not represented as active navigation features. The route inventory distinguishes directly rendered page components from two compositional TSX files. Browser journeys cover critical workflows and role entry points, but a passing domain journey is not proof of every one of the 89 page components under every role, error, loading, and responsive state; direct gaps are listed in `FRONTEND_TEST_REPORT.md`.
