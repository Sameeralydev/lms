# Phase 07 learning endpoint authorization matrix

Reviewed 2026-10-27. Route inventory command: `php artisan route:list --path=learning --except-vendor` (exit 0, 39 routes). This matrix records implemented boundary checks and actual feature coverage. “Representative” means the workflow has a positive and/or adversarial test, not that every route has a separate negative test.

All endpoints are nested below authenticated tenant workspace routes and the `learning.delivery.view` tenant permission. Domain workflows additionally verify current tenant membership, institution/campus scope, current user identity where applicable, workspace assignment and operation-specific capability. Record IDs and caller-supplied tenant identifiers do not establish authorization.

## Cross-cutting review findings

- Laravel route middleware enforces authentication and tenant permission before controllers. Controllers resolve resources through tenant-scoped models/services, while workflows repeat domain checks for mutation and learner access.
- Feature tests include tenant IDOR attempts, foreign workspace/course/media/session/template access, campus restriction, revoked membership, learner misuse of staff actions, author/reviewer/publisher separation, invalid or expired release exceptions, inactive/revoked media and learner restrictions from template/analytics routes.
- Existing protection for concurrent mutations uses transactions, `lockForUpdate`, idempotency constraints or optimistic `lock_version` depending on the aggregate. These controls are code-reviewed but must still be verified using the missing deterministic two-worker MySQL tests.
- No cross-tenant authorization is inferred from an ID, route slug, host header or frontend visibility. The UI hiding a control is not considered an authorization control.
- Coverage remains **PARTIAL**: this is not a passing endpoint-by-endpoint adversarial matrix. The listed outstanding tests are part of Phase 07 acceptance and are not waived by this report.

## Critical gate closure update - 2026-10-28

The previous coverage summary is historical. `CourseDeliveryTest::test_every_registered_learning_route_rejects_guest_nonmember_and_revoked_members_without_mutation` now derives the registered `tenant.learning.*` routes from Laravel's route collection and asserts the expected 39-route inventory. Its parameterized adversarial cases cover applicable unauthenticated guest, authenticated nonmember, revoked membership, wrong tenant, forged resource IDs and wrong workflow role; wrong-campus access is exercised for workspace-scoped read/HEAD routes. Resource parameters and required role/capability are taken from each route's middleware/definition where applicable. The test compares learning and audit row counts before/after denials to detect unauthorized mutation. SQLite focused evidence: 1 test passed / 166 assertions; full MySQL suite includes the test and passed. A second institution inside the same tenant is structurally impossible under the locked Phase 02 model, so �wrong institution within tenant� is not a valid fixture; cross-tenant isolation is exercised instead.

This route matrix is automated feature coverage, not a claim that every possible workflow state or production integration has been exhaustively modeled. The tenancy exception is documented in `PHASE_07_ARCHITECTURE.md`.
